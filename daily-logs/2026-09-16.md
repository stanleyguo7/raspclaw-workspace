# 2026-09-16

## 完成项

- 将 Zidoo Z10 Pro 的 CloudDrive2 从 0.8.9 升级到 1.0.17。
- 解决 Android 9 seccomp 与 app 存储命名空间导致的 FUSE 挂载问题。
- 在 AList 创建专用只读 WebDAV 访问，CloudDrive2 挂载夸克目录到 Zidoo 内置存储路径。
- 排查 CloudDrive2“能看到文件但无法播放”：确认夸克 302 直链因缺少签名所需请求头返回 412，将 AList 夸克 WebDAV 策略恢复为 `native_proxy`。
- 将 AList 从 3.58.0 升级到 3.64.0，夸克驱动自动迁移为 3 路、每片 10 MiB 的分片下载；Zidoo 连续读取实测约 6.1 MiB/s（约 49 Mbit/s）。
- 通过 CloudDrive2 API 重置并恢复 `/sdcard/mnt/CloudDrive` 挂载，重新绑定 Android runtime 存储命名空间；自动守护定时器保持启用。
- Zidoo 海报墙改用 `storage://mnt/CloudDrive/movie`，移除 rasp2 的 SMB movie/show 来源。
- 在 rasp2 启用 `zidoo-clouddrive-ensure.timer`，每 2 分钟检查并恢复 Zidoo CloudDrive2 挂载。
- 停止并禁用 rasp2 的 Samba 服务，关闭 UDP 137/138 与 TCP 139/445。
- 将服务脚本、systemd 单元、架构、缓存参数、验证和回滚方法写入仓库。
- 继续排查原生播放器失败：确认 `DvdPlayer` 被 SELinux 拒绝访问 `fuse:s0`，以最小只读策略规则修复，SELinux 保持 Enforcing；守护脚本会按 Zidoo boot ID 重新加载规则。
- 修复 CloudDrive2 重启后 Android app 命名空间保留失效 FUSE 的问题：守护脚本先 lazy-unmount 旧 runtime 绑定，再绑定当前挂载并重启图库/海报墙进程。
- 实播确认还有独立的上游限制：AList/夸克原始文件随机 Range 请求出现 416、context canceled 和 CloudDrive2 file corrupted；37 GB 4K DV 测试文件的夸克转码链接返回 plf_invalid。CloudDrive2 目录可用，但夸克视频未达到稳定播放条件。

## 后续观察
